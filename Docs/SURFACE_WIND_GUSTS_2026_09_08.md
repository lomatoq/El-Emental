# Continuous ground wind

Working tree on main, base 1235579, September 8. Source implementation; Unity validation remains coordinator-owned and pending.

Ground dust now samples one continuous position/time wind field instead of assigning a sine phase from each particle's reusable slot. A 24m gust travels downwind over 10 seconds with bounded +/-18% speed modulation and gentle tangent meander. Nearby wisps share the same motion. Spawn and live updates use the same evaluator; Reduced Motion retains steady reduced speed without gust/turbulence. Setting both strengths to zero restores steady flow.

The pure `EarthSurfaceWindPolicy.GustVelocity` owns the mathematical field only. `EarthSurfaceWindDust` owns particle updates and existing ground projection. Profiles expose strength, period, wavelength and turbulence. No emission, card silhouette, alpha, texture, shader, particle count, scene, fire or physical impact behavior is changed. Ground sampling remains four probes/frame: edge behavior still requires visual review.

Research: [Unity Noise Module](https://docs.unity3d.com/6000.0/Documentation/Manual/PartSysNoiseModule.html) establishes turbulence as a particle motion tool. A small explicit tangent field is used here because the adapter overwrites velocity and constrains support height. [URP particle reference](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/particles-unlit-shader.html) explains soft intersection fading; existing depth fade and premultiplied shading are retained. The renderer uses the existing profiler marker `Elemental.VFX.SurfaceWindDust`; performance is not inferred from particle count.

Validation handoff: run `Elemental.Tests.EditMode.EarthSurfaceWindPolicyTests` (six tests: existing tangent/fallback and new bounded curved normals, nearby spatial/temporal continuity, travelling front, zero-strength baseline). Then run `Elemental.Tests.PlayMode.EarthSurfaceWindDustProductionTests.SavedArenaHasPersistentSurfaceDriftAndDenserStoneWakes`; it already writes `BuildReports/SurfaceWindDust` production captures and CPU marker report, exercises Reduced Motion, and unloads its additive scene. Its scene load is not regeneration.

Art gate: inspect 10 seconds of ground drift with the existing gameplay camera, then a low oblique view near a settled stone cluster and a platform edge. Wisps should move together without lockstep identical silhouettes, never bob vertically or snap at phase changes. Check day/dusk/night and existing impact dust. The test captures prove participation, not artistic acceptance. Suggested new-cost targets (unmeasured): zero steady-state allocation and <=0.2ms CPU p95; collect player GPU delta separately. No new stone shader pass is included: fresh AO/material fixes already exist and further texture/noise changes have no representative A/B evidence yet.
