# El-Emental — актуальный геймплейно-технический справочник

Статус: рабочая документация Earth Core V4.2 implementation pass

Дата сверки с кодом и профилями: 2026-08-20

Основная QA-сцена: `Assets/Elemental/Content/Scenes/EarthPolishLab.unity`

Версия проекта: Unity `6000.5.7f1`, Universal Render Pipeline `17.5.0`

Этот документ описывает только реально существующие в репозитории системы. Он не является списком идей из ранних планов. Числа ниже взяты из текущих `ScriptableObject`-профилей или из runtime-кода; при изменении профиля поведение может отличаться без перекомпиляции кода.

## 1. Коротко: что это за игра сейчас

Текущий вертикальный срез — физическая магия земли на маленькой сферической планете. Игрок не выбирает заклинание из длинного хотбара: один набор кнопок получает разный смысл из цели под курсором, формы жеста, длительности удержания и модификатора `Shift`. V4.1 добавляет общий язык форм земли и отдельный presentation-слой хореографии, не перенося физическую authority в Animator, VFX или звук.

Основная цепочка ощущений:

`намерение игрока → физическая масса → столкновение → локальное разрушение → новые управляемые куски → восстановление или следующий бросок`.

Каноническая физика отделена от визуальных эффектов. Пыль, тряска камеры, свечение и исчезновение косметических сколов не решают, сломалась ли стена. Это решают импульс, энергия, связи конструкции и опора на землю.

## 2. Управление

### 2.1. Базовые кнопки

| Ввод | Действие |
|---|---|
| `W / S` | движение вперёд / назад по касательной к планете |
| `A / D` | поворот влево / вправо в активном tank-steering режиме; `W / S` дают поступательное движение |
| мышь | прицел, жесты и смещение точки внимания камеры |
| `Q` | сменить плечо камеры |
| `Esc` | отменить активный приём |
| `ЛКМ` | сформировать, схватить, вырвать, нарисовать или выпустить землю — по контексту |
| `ПКМ` | векторный толчок или усиление удерживаемого камня |
| `СКМ` | gravity grip; круговым жестом — разбор/восстановление конструкции |
| колесо | параметр активного приёма: дистанция, размер, высота, толщина или фаза брони |
| `Space` | заряжаемый столб-прыжок; при падении — амортизатор |
| `Shift + Space` | заряд паутинной земляной волны |
| `Shift + Space + ЛКМ` | резонансная левитация камней вместо волны |
| `Shift + СКМ` | каменная броня |
| `Shift + W` | земляная платформа-плуг |

### 2.2. Приоритет конфликтующих сочетаний

`EarthActionRouter` — единственный владелец пересекающегося Earth-ввода. Приоритет зафиксирован так:

1. уже активная сессия или `Cancel`;
2. `Shift + СКМ` — броня;
3. `Shift + Space` — волна либо резонанс;
4. `Shift + W` без кнопок мыши — плуг;
5. `СКМ` — gravity grip/repair;
6. `ЛКМ` — quick-stone, grip, pluck или рисование;
7. `ПКМ` — векторный толчок;
8. обычный `Space` — столб или амортизация.

Окно выбора между волной и резонансом длится `0.15 с`. Если в это окно удерживается или нажимается `ЛКМ`, сессия становится резонансом. После фиксации режима остальной конфликтующий ввод блокируется до отпускания или отмены.

## 3. Приёмы магии земли

### 3.1. Обычный захват и формирование камня — ЛКМ

Если под курсором уже есть физический камень, осколок стены/платформы, отделённая ячейка волны или другой совместимый Earth-объект, `ЛКМ` захватывает его. Пока кнопка удерживается:

- камень следует за мировой точкой на луче камеры пружинно, без parenting к персонажу;
- колесо меняет дистанцию удержания;
- движение курсора задаёт целевую позицию и скорость;
- `ПКМ` во время удержания накапливает силу и добавляет направленную скорость;
- отпускание `ЛКМ` сохраняет физический импульс вместо телепортации.

Если под курсором земля, удержание формирует новый объём и вырывает его из поверхности. Извлечённый объект использует один из выпуклых скошенных/сколотых каменных мешей и становится обычным физическим телом.

### 3.2. Быстрый камень — два коротких ЛКМ

Первый короткий клик по земле поднимает маленький камень за `0.15 с`. Второй клик в течение `0.42 с` буферизуется даже во время выхода камня из поверхности и запускает его в ближайший `FixedUpdate`.

Текущие параметры:

- скорость: `30–38 м/с`;
- начальный объём: `18%` обычного формируемого камня;
- если второго клика нет, камень освобождается в обычную физику и не следует за персонажем.

### 3.3. Вырвать ячейку из стены или платформы — удержать ЛКМ

При нажатии на целую конструкцию система сначала фиксирует её как `IEarthPluckableStructure`.

- удержание без заметного движения примерно `0.24 с` вырывает одну fracture-ячейку в точке прицела;
- связи этой ячейки повреждаются локально;
- остаток конструкции продолжает опираться на неповреждённые foundation-ячейки;
- вырванный кусок сразу переходит в обычный телекинетический захват;
- если вместо удержания начать рисовать, тот же контакт становится основанием для стены на выбранной грани.

### 3.4. Стена — прямой жест ЛКМ

Достаточно прямой протяжённый жест создаёт стену. Жест фиксируется в одной локальной плоскости поверхности от pointer-down до commit.

- колесо меняет высоту;
- `Shift + колесо` меняет толщину;
- высота стены в production-настройке ограничена мягким геймплейным диапазоном setup-сцены до `10.5 м`;
- подъём занимает `0.36–0.92 с` в зависимости от размера;
- основание строится по настоящей хорде и погружается в планету минимум на `0.42 м`, с дополнительным запасом видимой поверхности `0.55 м`;
- автоматическое разрушение по таймеру выключено (`automaticCrackDelaySeconds = 0`).

Стены разрешены не только на планете. Стабильные верхние и боковые грани стен/платформ предоставляют локальный frame; на боковой грани новая стена поднимается перпендикулярно этой поверхности. Свободные обломки основанием не являются.

Перед подъёмом выполняется проверка объёма пересечения. Старая конструкция, через которую строится новая стена, получает локальный construction impact; новая стена не повреждает сама себя.

### 3.5. Платформа — нелинейный или замыкаемый жест ЛКМ

Дуга, П-образный или другой достаточно нелинейный контур выбирает платформу. Контур проецируется в локальную плоскость стабильной верхней поверхности и замыкается.

- допустимая площадь: `0.8–75 м²`;
- одновременно: до `6` активных платформ;
- высота: `0.6–22 м`, мягкий порог стоимости — `8 м`;
- колесо меняет высоту;
- `Shift + колесо` записывает наклон;
- подъём занимает `0.52 с`;
- верхняя физическая опора активируется сразу при начале подъёма.

Платформа реализует `IMovingSurface`: персонаж регистрируется как rider, переносится скоростью опоры, может ходить и прыгать, а при прыжке наследует скорость платформы. Своя поднимающаяся платформа имеет защитный период от ложного impact debt/ragdoll; сильный внешний удар после него остаётся разрушительным.

На вертикальной грани нелинейный жест платформы отклоняется: там разрешена только перпендикулярная стена.

### 3.6. Векторное поле — ПКМ

Нажатие фиксирует одну ближайшую совместимую цель под курсором: камень, осколок, столб, стену или другую физическую Earth-цель.

Режим определяется движением и временем:

- короткий тап — компактный реактивный импульс;
- удержание — непрерывное управляемое поле;
- быстрый жест мышью с отпусканием — projectile flick вдоль экранного вектора и луча камеры.

Текущая настройка поля:

- непрерывная сила: `4200 Н` до массовых ограничителей;
- заряд до полного: `1.35 с`;
- предел скорости камня: `32 м/с`;
- предел скорости целой стены: `14 м/с`;
- точный hold ограничен `9 м/с` для камня и `6.5 м/с` для стены;
- коэффициент рычага стены: `72`;
- импульс отпускания: `260–2400 Н·с`, минимум для стены `650 Н·с`.

Во время магического скольжения снижается сопротивление основания стены, её ориентация стабилизируется относительно локального `up`, а коллизия с кастером временно подавляется до безопасного расхождения.

### 3.7. Gravity grip и круговой repair — СКМ

СКМ фиксирует цель при нажатии, а не переопределяет её каждый кадр. Сессия может держать до `48` целей в радиусе `7.5 м`.

Для свободной земли и осколков:

- цели собираются вокруг точки прицела пружинно-демпфированным кластером;
- компенсируется локальная планетарная гравитация;
- максимальная скорость — `16 м/с`;
- куски не уменьшаются, пока захвачены;
- после отпускания продолжают падать и сталкиваться, а visual shrink идёт параллельно физике.

Для стены или платформы:

- выбранная конструкция остаётся владельцем всей сессии;
- новые куски, появившиеся при fracture, добавляются в grip в тот же physics tick;
- движение мыши по часовой стрелке восстанавливает конструкцию;
- против часовой стрелки — последовательно разбирает связи;
- полный фазовый диапазон соответствует примерно `300°` жеста;
- при наличии всех кусков repair возвращает точные rest transforms и цельный proxy collider;
- потерянные куски дают честный частичный результат без создания новой массы.

Физическое восстановление проходит через capture → staging cloud → alignment → settle → reform bonds. Куски двигаются ограниченным PD-контроллером с активными столкновениями, а не телепортируются в место.

### 3.8. Столб-прыжок — удержать и отпустить Space

Под персонажем поднимается земляной столб и сообщает ему вертикальную скорость относительно локального `up`.

- полный заряд: `1.45 с`;
- изменение скорости: `12–25 м/с`;
- кривая заряда нелинейная (`chargeExponent = 1.55`), поэтому длинное удержание чувствуется сильнее короткого;
- столб использует поверхность планеты или стабильную платформу;
- скорость движущейся опоры наследуется;
- после запуска столб уходит обратно в землю до возвратной траектории игрока.

### 3.9. Амортизация падения — Space во время снижения

При снижении повторное удержание `Space` включает prediction точки приземления на локальной гравитации.

- горизонт прогноза: до `4 с`;
- активация с высоты около `3.2 м`;
- целевая скорость касания: не более `4 м/с`;
- амортизатор: примерно `2.4 × 1.7 м`;
- сжатие: `0.28 с`, уход в землю: `0.42 с`;
- собственный амортизатор не переводит персонажа в `FullRagdoll`.

### 3.10. Паутинная волна — Shift + Space

После окна аккорда `0.15 с` удержание заряжает волну, отпускание выпускает её по направлению движения/взгляда.

Волна использует шесть seeded радиально-спиральных топологий и геологические ячейки с `3–8` сторонами. Это не voxel-edit и не один Rigidbody на каждый визуальный камень.

Текущие границы:

- `6–8` рядов;
- дистанция `2–11.2 м`;
- размер ячейки `0.64–1.28 м`;
- высота от `0.28 м` до гребня `1.55 м`;
- скорость гребня `5.4 м/с`;
- подъём `0.30 с`, удержание гребня `0.04 с`, уход `0.32 с`;
- физический/визуальный пул — максимум `96` ячеек;
- выбранная ячейка может отделиться и стать обычной физической целью.

После прохождения гребня предыдущие ячейки сразу уходят назад, поэтому движется именно волна, а не одновременно поднятая решётка.

### 3.11. Резонансная полусфера — Shift + Space + ЛКМ

Если `ЛКМ` добавлен в первые `0.15 с` аккорда, волна отменяется и начинается резонанс.

- порог появления: `0.55 с`;
- полный заряд: `2.6 с`;
- камней: `8–28`;
- радиус выборки: `1.2–6.5 м`;
- жизнь построения после release: `1.5–6 с` по нелинейной кривой заряда;
- камни заполняют верхнюю полусферу и уменьшаются к краю;
- они следуют за персонажем пружинно, без parenting;
- `ЛКМ` выпускает ближайший к прицелу камень, удержание ведёт очередь с интервалом `0.11 с`;
- `ПКМ` выпускает остаток направленным залпом;
- скорость снаряда: `34 м/с`;
- свои снаряды игнорируют коллайдеры кастера до безопасного расхождения.

### 3.12. Каменная броня — Shift + СКМ

Броня имеет приоритет над обычным gravity grip. В production-профиле используется до `96` физических пластин. Они поднимаются из разных точек земли, собираются по поверхности анимированного Humanoid и остаются отдельными перехватывающими ударами телами. Персонаж остаётся видимым внутри внешней оболочки, а его исходные материалы больше не подменяются каменным материалом.

Пластины создаются детерминированно, но не выглядят копиями: меняются число граней, выпуклый силуэт, глубокие сколы, соотношение ширины/высоты, нижний скос, высота и смещение каменной «короны». Площадь покрытия при этом примерно сохраняется, чтобы разнообразие формы не превращалось в случайные дыры или взаимное проникновение. Через `MaterialPropertyBlock` добавлена ограниченная вариация наружного оттенка, macro-frequency и mineral amount без создания отдельных экземпляров материала.

Фазы колеса:

- `0–30%` — плотная броня по телу;
- `30–78%` — защитный купол радиусом до `2.5 м`;
- `78–100%` — свободная орбита радиусом до `3.2 м`;
- колесо вниз возвращает построение к телу;
- после `100%` две подтверждённые быстрые ступени вверх в течение `0.35 с` запускают радиальный разлёт `16–24 м/с` и полную паутинную волну.

В раскрытом состоянии:

- `ЛКМ` выпускает ближайшую к прицелу пластину; удержание стреляет очередью с интервалом `0.13 с`;
- `ПКМ` выпускает все оставшиеся пластины направленным веером;
- скорость прицельной пластины — `31 м/с`;
- выпуск не сообщает обратный импульс персонажу;
- обычное отпускание `СКМ` превращает пластины в падающий debris с физикой и постепенным уменьшением.

Компактная броня не перекрашивает исходный renderer персонажа: герой сохраняет свой материал, а камень остаётся внешней оболочкой. В центре головы и груди предусмотрены фронтальные apertures: пластины смещаются к боковым швам, а coverage scale в зоне читаемости может снижаться до `0.38`; боковые области и конечности этим правилом не уменьшаются.

Камера не использует controlled-magic layer как препятствие для Cinemachine. Дополнительно на `Camera.onPreCull` работают два узких коридора видимости к груди и голове: только перекрывающие их renderer-ы пластин временно скрываются. Коллайдеры, масса, перехват ударов и target handle при этом остаются активными. Это render-only защита кадра, а не отключение физической брони.

### 3.13. Земляная платформа-плуг — Shift + W

Приём запускается только при движении вперёд, на стабильной поверхности и без другой активной магии.

- платформа выходит за `0.16 с`;
- размер текущего профиля: ширина `2.35 м`, длина `3.9 м`, поднятый нос `0.82 м`;
- скорость нелинейно растёт от `4` до `13 м/с` за `1.2 с`;
- персонаж едет как rider движущейся опоры, а locomotion-анимация ног намеренно получает скорость `0`;
- нос выполняет ограниченный sweep и создаёт настоящие impacts по камням и конструкциям (`noseImpactImpulse = 2400`);
- след, пыль и мелкие камни показывают разрез земли без постоянной перестройки voxel SDF;
- после отпускания `Shift` платформа уходит/разрушается за `0.45 с`, персонаж сохраняет ограниченную касательную скорость.

### 3.14. Приёмы других elemental labs

В репозитории существуют отдельные лабораторные реализации воздуха и термальной воды. Они не входят в shipping-грамматику `EarthPolishLab`, но являются исполняемыми системами в своих сценах:

| Элемент | Debug-ввод | Способности |
|---|---|---|
| Air | слоты `1–4` в Air lab | `GustCorridor`, `Vortex`, `LiftColumn`, `AirBrake` |
| Fire | `F`, затем слоты `1–2` | `HeatJet`, `ThermalFocus` |
| Water | `R`, затем слоты `1–4` | `GatherWater`, `WaterJet`, `FreezeBridge`, `SteamBurst` |

Цифровые слоты являются development/debug forcing, а не частью основного Earth-интерфейса. Earth-форма определяется контекстом и жестом, поэтому `SelectEarthAbility` сохранён только как bridge для replay/tests.

## 4. Цели и физические взаимодействия

Единый target-query распознаёт capabilities, а не список случайных компонентов: `Grab`, `Push`, `Gravity`, `Damage`, `Pluck`, `Repair`, `Surface`, `Draw`.

Поддерживаемые физические цели:

- целая стена и платформа;
- любой активный осколок стены/платформы;
- обычный извлечённый камень;
- ячейка волны или столб;
- пластина брони после выпуска;
- резонансный снаряд;
- совместимый динамический impact target.

Быстрые тела включают CCD после `18 м/с`. Для камней дополнительно работает oriented `BoxCastNonAlloc` между предыдущей и следующей физической позицией; первый swept-contact возвращает тело в точку удара, создаёт один `EarthImpactEvent` и не дублируется последующим collision callback.

Профиль физического ощущения:

- dynamic/static friction камня: `0.62 / 0.78`;
- bounciness: `0.08`;
- максимум угловой скорости: `22 рад/с`;
- пороги кинетической энергии: лёгкий `45 Дж`, тяжёлый `650 Дж`, катастрофический `2600 Дж`.

### 4.1. V4.1 Earth Shape Grammar

`EarthShapeGrammar` задаёт компактный детерминированный язык каменных силуэтов из `12` семейств:

`Compact`, `FlatSlab`, `TallCrag`, `OffsetCrown`, `Layered`, `FiveFacet`, `Eroded`, `OreHeavy`, `Wedge`, `Disc`, `Prism`, `BroadCrown`.

Форма выбирается из стабильного seed, составленного из world seed, ID исходной материи, ID техники, поколения и variation salt. Поэтому replay одного и того же события воспроизводит тот же камень, но последовательность разных объектов не обязана выглядеть одинаково.

`EarthShapeDiversityTracker` хранит окно последних сигнатур, по умолчанию `16`, и пробует до `12` детерминированных кандидатов, чтобы не повторять соседние силуэты. Сигнатура учитывает семейство, aspect bucket, crown bucket и silhouette hash. Геометрия семей различается числом граней, пропорциями, короной, фазой, плоской вершиной и слоистостью; faceted-вид сохраняется раздельными render-вершинами граней.

Если в `EarthFragmentPool` или `EarthRockDebrisPool` отсутствует актуальная библиотека либо обнаружены старые `Beveled Earth Block`, runtime создаёт все `12` вариантов через `EarthRockMeshFactory`. Фрагменты конструкции и ballistic/accretion debris выбирают их через тот же anti-repeat, но с разными technique/salt seed. Каждый сгенерированный mesh проходит `EarthMeshIntegrityGate`; для физических целей используется допустимый convex collider. Пулы удаляют созданные runtime-меши при завершении своего lifecycle.

Важно: grammar отвечает за разнообразие формы, но не отменяет conservation/lifecycle. Debris остаётся динамическим и сталкивающимся во время уменьшения; visual scale достигает нуля только перед возвратом в пул.

### 4.2. Физическая цель Earth Combat Dummy

`EarthCombatDummy` — читаемая физикой мишень в `EarthPolishLab`, а не полноценная система здоровья или отдельный владелец bending-логики. Она принимает тот же `EarthImpactEvent` и проходит состояния:

`Grounded → Braced → Staggered → FullRagdoll → Recovering`.

По умолчанию порог stagger равен `180 Н·с`, full ragdoll — `720 Н·с`. Кинетическая энергия может усилить effective impact до коэффициента `1.35`, а brace делит воспринимаемый импульс на `1.65`. После выдержки состояния recovery за `0.42 с` выравнивает Rigidbody относительно локального планетарного `up`, гасит угловую скорость и возвращает мишень в `Grounded` либо `Braced`. Это позволяет в лаборатории различать лёгкое касание, stagger и тяжёлый снос одной и той же физической шкалой.

## 5. Разрушение и структурная устойчивость

Стена и платформа используют настоящий трёхмерный prefracture, а не 2D Voronoi, вытянутый на всю высоту.

Текущий `EarthStructureFractureProfile`:

- стена — `40` объёмных ячеек;
- платформа — `36` ячеек в production-профиле;
- минимум `3` слоя по высоте/толщине;
- отношение P90/P10 объёма — не менее `3`;
- слабый удар освобождает до `4` локальных ячеек;
- средний — до `8`;
- construction impact — `2850 Н·с`;
- тяжёлый удар умножает воздействие на `4`.

Каждая ячейка — закрытый выпуклый многогранник. Соседние ячейки получают согласованные общие плоскости; collider mesh готовится при создании/authoring, а не в collision callback, и остаётся в пределах PhysX-ограничения `255` треугольников/вершин для convex cooking.

Bond/island solver разделяет:

- поддерживаемые foundation-острова — продолжают стоять и принимать следующий урон;
- неподдерживаемые острова — переходят в динамическую физику;
- локальный скол от небольшого камня;
- массовое разрушение от тяжёлого блока;
- дочерние конструкции, привязанные к фактической опорной ячейке родителя.

Repairable structural pieces не исчезают по скрытому таймеру. Косметические chips и released debris могут уменьшаться, но сохраняют радиальную гравитацию, скорость и столкновения до scale `0`, после чего возвращаются в пул.

## 6. Планета, гравитация и voxel-технология

`PlanetWorldProfile` — единый источник параметров мира:

- радиус по умолчанию: `24 м`;
- поверхностная гравитация: `14 м/с²`;
- seed: `57824`;
- шум поверхности: `0.35 м`;
- voxel cell: `1 м`;
- chunk resolution: `16`;
- очередь render mesh: `8` чанков/кадр;
- очередь collider mesh: `4` чанка/кадр.

Радиус меняется только вне Play Mode через `Elemental Suite → World & Space → Apply / Rebuild World`. Допустимые диапазоны: Native High `12–80 м`, Native Low `12–48 м`, WebLab `12–24 м`.

Каноническая земля — аналитический base SDF плюс упорядоченный журнал edits. Render/collision meshes являются восстанавливаемыми кэшами. Начальная генерация выбирает только чанки, чьи AABB пересекают консервативную оболочку поверхности, а не весь куб вокруг планеты.

Гравитация радиальная, поэтому `PlanetMotor`, камера, частицы, debris, платформы и небесные вычисления используют локальный `up`, а не глобальную ось Unity Y.

## 7. Персонаж, движение и анимация

### Физическое движение

`PlanetMotor` двигает Rigidbody по касательной к планете и отдельно согласует ориентацию с локальным `up`.

Текущий feel-профиль:

- скорость: `7.2 м/с`;
- ускорение/торможение: `48 / 62 м/с²`;
- контроль в воздухе: `0.32`;
- обычный jump fallback: `8 м/с`;
- turn response: `170°/с`;
- coyote time: `0.12 с`;
- jump buffer: `0.14 с`;
- максимальный уклон: `55°`;
- ground snap: `3.5 м/с`;
- во время cast скорость уменьшается до `36%`, при сильном brace — до `18%`.

Движущиеся платформы передают скорость опоры, а collision/support solver различает собственный подъём, внешний удар и потерю опоры.

### Humanoid presentation

Текущий playable-персонаж — Mixamo `X Bot` без шляпы и шлема, импортированный как Unity Humanoid. Он заменил KayKit Knight в production-пути, чтобы очистить обзор и получить устойчивую человеческую походку. Из локального набора Mixamo используются `Walking`, `Walking Backwards` и `Punching`; KayKit-клипы остаются только резервом для бега и части spellcasting-поз. Источники, условия использования и SHA-256 всех четырёх FBX записаны в `Docs/THIRD_PARTY_NOTICES.md`.

`CharacterPresentationProfile` позволяет заменить модель без изменения gameplay-кода. Сейчас:

- масштаб модели `1.08`;
- root motion выключен — физическое движение остаётся у `PlanetMotor`;
- locomotion blend: `0.12 с`;
- casting blend: `0.10 с`;
- вес hand IK: `0.92`;
- Animator работает в `AlwaysAnimate` и получает `Speed`, `Grounded`, `VerticalSpeed`, `Cast`, `CastKind`, `Impact`;
- locomotion blend использует подписанную скорость вдоль `FacingForward`: `Walking Backwards = -2`, `Idle = 0`, `Walking = 2`, резервный `Run = 6`;
- `VectorPush` использует Mixamo `Punching`, а восемь дочерних earth-motion состояний повторно привязываются после импорта FBX, чтобы импорт не оставлял Animator со stale motion references;
- upper-body слой `Earth Magic Upper Body` подмешивается независимо от ног;
- руки IK-направляются к held body, gravity focus или vector-field point;
- при сильном cast foot IK фиксирует стопы, компенсирует таз и расширяет стойку;
- на surf presentation speed специально равен нулю, чтобы персонаж не «бежал» по доске.

### Bending choreography V4.1

Gameplay передаёт presentation не название конкретного клипа, а `BendingPoseRequest`. В запросе находятся:

- `EarthTechniqueId` и фаза `Idle / Acquire / Root / Load / Strike / Sustain / Recover`;
- касательное направление действия и локальный `up`;
- управляемая масса, effort, grounding и precision;
- ведущая рука и стабильный `EarthMatterId` цели.

`EarthPoseSolver` переводит запрос в один из двух диалектов движения. `RootedPower` используется для стены, платформы, столба-прыжка, волны, брони, repair, wall slide и fracture fan; более точные/мобильные действия используют `CompactTactile`. Результат задаёт сжатие таза, ширину стойки, вес верхней части тела и короткий локальный pose hold.

`EarthChoreographyDirector` является только presentation-компонентом. Он передаёт в Animator доступные параметры `EarthEffort`, `EarthBrace`, `EarthGrounding`, `EarthPrecision`, `EarthPhase`, `EarthDialect`. На входе в тяжёлый `Strike` он может замедлить только Animator этого персонажа до `0.02` на `0.025–0.078 с`, после чего возвращает скорость `1`. Глобальный `Time.timeScale`, физический tick и результат заклинания не меняются.

### Active ragdoll

`ActiveRagdollPuppet` имеет состояния animated motor, stagger и full ragdoll. В full ragdoll Animator отключается. Recovery выравнивает visual root относительно локальной гравитации и возвращает locomotion без `Animator.Rebind`, потому что runtime-parenting rigid частей под Humanoid bones иначе может заморозить позу.

## 8. Камера

Основная камера — Cinemachine `3.1.7`:

- `CinemachineThirdPersonFollow` отслеживает отдельный aim pivot;
- world-up frame следует за `PlanetMotor.LocalUp`, поэтому горизонт не заваливается вместе с pitch;
- gameplay virtual camera имеет priority `100`;
- стартовая дистанция около `7.5 м`, состояние камеры ограничивает её диапазоном `6.6–8.5 м`;
- pointer bias сдвигает фокус вперёд/вверх-вниз, но имеет dead zone `0.20 × 0.18` viewport;
- ближайшая/дальняя точка фокуса на земле: `4.4 / 11.4 м`;
- максимальная скорость фокуса: `18 м/с`;
- `Q` меняет плечо;
- режимы Explore, DrawStructure, HoldMass и Airborne меняют distance, height, FOV, damping и pitch;
- `PlanetCameraRig` остаётся только compatibility-слоем для telemetry и presentation impulses, пока Cinemachine владеет transform.

Камера игнорирует controlled magic в obstacle solver, чтобы броня/камни не толкали её внутрь персонажа. При активной броне solver увеличивает authored distance на `0.85–1.75 м` по мере раскрытия оболочки; итоговый armor-диапазон ограничен `7.45–10.25 м`, а переход сглаживается быстрее обычного camera state.

Render-only visibility guard перед cull скрывает только те пластины, которые перекрывают узкие sightline-коридоры к голове и груди, с release-hysteresis `0.08` против мерцания. Вместе с фронтальными apertures головы/торса это сохраняет лицо, центр тела и прицел читаемыми, не меняя collider, массу или способность пластины перехватить удар.

## 9. Шейдинг и материалы

### Earth master material

Основной shader: `Elemental/SG Earth Master` (`EarthTriplanar.shader`), URP Forward.

Проекция имеет два режима:

- стены, камни, броня и осколки используют scale-correct object-local frame: текстура движется и вращается вместе с телом, но размер texel остаётся в метрах;
- voxel chunks используют одну общую planet-local матрицу, поэтому texture coordinates не перезапускаются на каждом чанке и не «плывут» при движении мира.

Слой материала:

- triplanar albedo;
- triplanar normal;
- mask map: AO и roughness;
- широкая deterministic macro-вариация;
- weathered exterior и более холодный/тёмный fresh fracture interior;
- cavity darkening;
- пыль, зависящая от нормали и cavity;
- редкие mineral veins;
- ограниченный оранжевый magic accent;
- main light shadows, additional lights, SH ambient и fog.

Текущий high-профиль:

- mid tiling `0.48`, micro tiling `4.2`;
- micro normal fade `9–24 м`;
- normal strength `0.72`;
- macro variation `0.16`;
- cavity `0.46`, dust `0.16`;
- exterior smoothness `0.07`, interior `0.025`.

Native Low включает `_EARTH_DETAIL_LOW`, убирает micro-normal sample и снижает лимиты feedback.

### Baked face masks

Render-вершины fracture pieces кодируют:

| Канал vertex color | Назначение |
|---|---|
| R | weathered exterior |
| G | fresh interior |
| B | magic activation mask |
| A | cavity/depth |

Collider mesh отделён от render mesh; визуальная детализация не увеличивает каноническую collision-топологию.

### Render policy

- URP остаётся в Forward; Forward+ не включается без A/B capture;
- GPU Resident Drawer не используется для динамических fracture pieces;
- Tier-C visual debris рисуется одним `Graphics.RenderMeshIndirect` вызовом из фиксированного буфера до `512` экземпляров; это только presentation без collider/damage authority;
- официальный VFX Graph подключён точечно для `EarthImpactVFXGraph` и `EarthReturnVFXGraph`; графы получают уже подтверждённые события и не решают hit/fracture/return;
- при отсутствии compute/indirect support слой корректно отключается, не создавая `GraphicsBuffer` и не меняя каноническую физику;
- HDRP, ECS/Havok и сторонняя fracture physics не добавлены;
- surface scars используют URP decal renderer feature и кольцевой пул.

## 10. Космос, свет, атмосфера и метеоры

Физическая планета остаётся около мирового начала координат. Орбита является scaled-space presentation: небесные тела пересчитываются вокруг камеры по направлениям, поэтому не получают ближний параллакс и не двигают PhysX в огромные координаты.

### Celestial system

`CelestialEphemerisSolver` выдаёт sun direction, moon direction/phase, time of day, orbit phase и night factor.

Текущий профиль:

- день: `480 с`;
- визуальный год: `1440 с`;
- орбита луны: `240 с`;
- наклон оси: `18°`;
- старт времени: `0.21`;
- интенсивность дневного Directional Light: `1.45`;
- moonlight: `0.08`;
- scaled-space distance: `1200 м`.

Видимый sun disc и Directional Light получают один вектор. Ambient, цвет ключевого света и ночной коэффициент меняются плавно. Луна и далёкая планета используют direction-based impostor/mesh presentation; terminator луны вычисляется тем же направлением солнца.

### Procedural sky

Один seeded skybox shader заменяет множество GameObject-звёзд. Он создаёт мелкие и hero stars, цветовую температуру, слабую nebula-полосу, дневной gradient и солнечный диск. Skybox принудительно пишет hardware far plane, что важно для reversed-Z D3D11.

### Атмосфера

В URP используются два слоя:

1. depth-aware Full Screen Pass с ограниченным ray-sphere Rayleigh/Mie scattering;
2. прозрачная outer limb-shell для читаемого края планеты.

Текущий внешний радиус — `1.055 ×` радиуса планеты. Rayleigh — холодный синий (`strength 2.1`), Mie — тёплый солнечный (`0.7`), horizon strength — `2.4`, night opacity — `0.12`.

### Метеоры

- декоративные streak-метеоры: в среднем `0.15/с`, пул `64`;
- физические: каждые `35–55 с`, максимум `4`;
- скорость: `24–42 м/с`;
- радиус: `0.25–0.9 м`;
- плотность: `1800 кг/м³`;
- кратер: `0.4–2 м`;
- не больше `2` terrain edits в секунду;
- физические метеоры используют CCD и создают единый impact event при ударе.

## 11. VFX, impact feedback и HUD

`EarthImpactEvent` переносит импульс, кинетическую энергию, массу, относительную скорость, точку, нормаль и material kind. Presentation батчит плотные всплески в пределах кадра, но не меняет damage/fracture.

Текущий high-профиль feedback:

- до `52` пылинок и `14` mesh chips на один оценённый эффект;
- frame batch ceiling: `72` dust и `20` chips;
- кольцо из `40` persistent decals;
- scar lifetime `24 с`, fade `5 с`, draw distance `42 м`;
- яркие sparks появляются только на исключительной энергии;
- camera impulse масштабируется логарифмически по энергии.

Все particles ориентируются по локальной нормали планеты. Косметический debris падает по радиальной гравитации и уменьшается одновременно с движением.

Earth HUD показывает только актуальный контекст: owner ввода, заряд/amount, quick-stone window, режим push, цель/фазу gravity gesture, integrity конструкции, фазу/overscroll брони, заряд и число камней resonance, скорость surf, preview стены/платформы и причину reject.

### Параметрический звук V4.1

`EarthAudioDirector` подписывается на канонические `EarthImpactEvent` и `EarthReturnEvent`, но ничего не решает в физике. Из параметров события он строит `EarthAudioResponse` с тремя слоями:

- `Body` — низкочастотная масса; зависит прежде всего от массы и импульса, дополнительно учитывает тип материала;
- `Crack` — удар/излом; зависит от импульса и кинетической энергии;
- `Grit` — мелкая каменная фактура; зависит от относительной скорости и энергии;
- `Pitch` понижается с ростом массы в диапазоне solver-а `0.55–1.65`.

Для возврата материи интенсивность учитывает массу, объём и этап `Captured / Subsurface / CommitSubmitted / Completed / Reversed / Jammed`. Каждый слой воспроизводится отдельным пространственным emitter-ом в точке события; сам общий Earth-magic root туда не перемещается. Текущие authoring-параметры директора — master volume `0.72`, spatial blend `0.68`, logarithmic rolloff `1.2–42 м` и слабый doppler `0.15`.

Пока bespoke-записи не подключены, runtime создаёт короткие процедурные fallback-клипы body/crack/grit. Это делает физическую причинность слышимой уже сейчас, но не следует считать финальным sound-content pass.

## 12. Архитектура

```text
Input System
  → EarthInputAdapter
  → EarthActionRouter / нормализованные жесты
  → команды и сессии Simulation
  → Earth Matter Kernel / Runtime PhysX / voxel / structure adapters
  → типизированные события и snapshots
  → BendingPoseRequest / EarthChoreographyDirector
  → Animation / Camera / VFX / Audio / HUD
```

Границы сборок:

- `Elemental.Core` — IDs, математика, время, сериализация;
- `Elemental.Simulation` — чистые правила gravity, bending, fracture, repair, voxel, celestial;
- `Elemental.Runtime` — Unity lifecycle, PhysX, мир и character adapters;
- `Elemental.Presentation` — камера, Animator, VFX, шейдеры, UI;
- `Elemental.Input` — Input System, sampling, context/intent routing;
- `Elemental.Authoring` — ScriptableObjects, validators, bakers и editor tools.

Ключевые правила:

- commands входят в simulation, typed past-tense events выходят;
- state идентифицируется стабильными ID и generation, а не `GameObject.GetInstanceID()`;
- ScriptableObject копируется в runtime state и не мутируется как глобальная переменная;
- presentation не становится authority физики;
- runtime-геометрия проходит `EarthMeshIntegrityGate`, а недопустимая winding/collider topology заменяется безопасным fallback, не «лечится» слепым пересчётом нормалей;
- нет глобального service locator;
- fixed physics tick — `60 Гц`, fields — `20 Гц`, thermal — `10 Гц`;
- горячие steady-state loops используют caller-owned/fixed buffers и рассчитаны на `0 B` managed allocations.

### 14.1. Фактический V4.2 rescue/hero pass

После video-audit в playable path внесены следующие изменения:

- MMB владеет RMB внутри активной gravity-session: короткий RMB даёт direct cluster throw, удержание сжимает кластер и выпускает mass-aware blast; self-collision grace действует только между кастером и запущенными телами;
- gravity кластер формирается в двух детерминированных боковых дугах; чем тяжелее объект, тем больше camera-clearance, поэтому hero debris не собирается в слепой cloud по центру кадра;
- `ConstructionOrientationMode` сохраняет authored/support frame. Стена на боковой грани больше не переворачивается в planet-up после push; на вертикальной опоре можно строить закрытую консольную платформу;
- platform fracture plan публикуется только после closed-topology court. Welded face cycles триангулируются заново, а non-manifold faces отсекаются до MeshCollider publication;
- ноги используют stable radial knee hints, плавный IK ramp и foot locks в `SupportFrameSnapshot`; движущаяся опора и surf переносят локальную точку стопы, а airborne гарантированно обнуляет foot IK;
- surf имеет четыре anti-repeat hero silhouettes, отдельный стабильный support collider, bounded rider-anchor correction, bank, ramp, brake и плотный шлейф срезанных камней;
- wave grammar выбирает шесть semantic families с anti-repeat вместо одной повторяющейся решётки;
- armor dome стал направленным многослойным щитом, orbit — пятью неидеальными встречно вращающимися bands в верхней полусфере. Wheel-down возвращает только существующие released plates в их persistent slots;

## 15. Что является experimental или ещё требует ручной оценки

- Качество camera/self-armor кадра необходимо оценивать в реальном Game View в движении; тест расстояния камеры не доказывает читаемость головы и груди, поэтому добавлен render-only sightline guard.
- Визуальное разнообразие, размеры и стык-в-стык packing брони — art/feel gate, а не только unit-test на количество пластин. Runtime дополнительно проверяет разные mesh-сигнатуры, конечные наружные нормали и предельное число глубоких пересечений.
- Процедурные body/crack/grit дают функциональный параметрический звук, но финальный набор записей, микс и perceptual loudness требуют отдельного content/feel pass.
- `EarthCombatDummy` — лабораторная шкала физических реакций, не финальный противник с AI, здоровьем и боевой анимацией.
- CPU P50/P95/P99 уже собраны в 10-минутном player stress; GPU P50/P95/P99 требуют видимого capture через Profiler/Frame Debugger, потому что hidden runner не вернул GPU timings.
- Холодный старт voxel render queue ранее давал заметные одноразовые пики; это startup debt, не steady-state frame time.
- Forward+, GPU Resident Drawer, HDRP, ECS и сторонняя fracture physics сознательно не используются без измеримого преимущества; VFX Graph применяется только двумя bounded consequence-графами.
- WebLab требует однократного подтверждения UAC для уже скачанного WebGL Build Support; до этого WebGL build не заявляется зелёным.
- Gate 8.5 ещё не закрыт: не выполнены 60-минутный player soak, полный ручной camera/readability sweep и формальная severity/waiver ревизия P2.
- Air, Fire и Water имеют отдельные lab-способности и authoring assets, но они не входят в текущую shipping Earth-грамматику. Цифры `1–4`, `F` и `R` остаются debug/lab-маршрутом для этих сцен.
