# CODEX_HANDOFF — EL EMENTAL / Stone UI

## Приоритеты интеграции

**Сохранить ручные положения HUD в актуальной сцене и настоящую сетевую логику.**
Архив — библиотека оформления и исходников, а не замена текущей сцены или проекта.

Перед изменениями согласовать владение файлами с соседней активной задачей и посмотреть
текущий diff. Не откатывать её изменения и не перезаписывать существующие сцены, префабы,
UXML/USS, `.meta`, backend, Input Actions, настройки камер, URP и Packages целиком.
Переносить оформление адресно, сохраняя существующие привязки и сериализованные значения.

**HUD:** сохранить текущие координаты, anchors, offsets, размеры, safe-area overrides,
порядок слоёв и привязки данных. `UI/Screens/HUD.uxml` — референсная компоновка, а не
обязательная миграция размещения. В `StoneTheme.uss` есть абсолютная геометрия HUD:
не применять её поверх ручного layout без отделения визуальных правил/локальных overrides.
`StoneUIController.ShowScreen()` вызывает `_root.Clear()` и клонирует дерево заново:
не назначать этот контроллер существующему HUD UIDocument. Новые меню подключать отдельно
или через текущий экранный роутер; живой HUD не пересоздавать ради смены скина.

**Сеть:** существующий сервис остаётся единственным источником истины для комнат, кодов,
подключения, отмены, результатов и rematch. Не заменять transport, протокол, формат кодов,
авторитетность, таймауты и обработчики. `StoneUIBackend.cs` — абстрактный адаптер,
а не реализация сети. В рабочей интеграции `demoMode=false`; `DEMO42` и preview-значения
не должны участвовать в реальной сессии. Подключать каждое действие одним путём
(event либо UnityEvent), без двойного вызова и повторных подписок.

## Подключение

1. Сначала внести `Assets/ElEmentalStoneUI/` в рабочую ветку адресным merge.
   `Source/`, `Tools/`, `Preview/` хранить как материалы разработки, не импортировать
   исходные атласы в runtime повторно. Сохранить существующие GUID и overrides проекта.
2. После вашей проверки компиляции использовать при необходимости
   `Tools > EL EMENTAL > Stone UI > 1 - Build library and prefabs`.
   Выходы: `Assets/ElEmentalStoneUI/Generated/` и
   `Assets/ElEmentalStoneUI/Resources/ElEmentalStoneUI/StoneUIAssets.asset`.
   Builder перезаписывает свои generated-префабы и часть настроек — не запускать
   поверх кастомизированных выходов без diff. Демо-сцены — только для отдельного просмотра.
3. Связать представление с текущим backend через `ActionRequested`, `InputBlockChanged`,
   `SettingsChanged`. Обратные данные: `ApplyHud`, `SetRoom`, `SetLoading`,
   `SetMinimap`, `ShowResult`, `ShowConnectionError`, `SetControlsText`, `ShowScreen`.
   Правила паузы, input gating, выход из сессии, mixer и чувствительность берутся
   из проекта. Дальние скалы подключать отдельной необязательной фазой, не менять
   радиус планеты, камеру, физику или сетевую сцену автоматически.

## Известные ограничения — исходники не исправлялись при упаковке

- Unity-компиляция, импорт, shader compilation, Play Mode, сеть и визуальная проверка
  не выполнялись. Ранее код ориентировался на Unity 6000.5.7f1 / URP 17.5.0;
  это не повод обновлять текущие версии проекта.
- Готовых `.unity`, `.prefab`, `.asset`, `.meta` в исходном переносимом наборе нет:
  они создаются вашей Unity/installer. Это ZIP с исходниками, не `.unitypackage`.
- `StoneUIInstaller` ссылается на **отсутствующий** `UI/StoneDefault.tss`.
  Использовать существующий совместимый ThemeStyleSheet проекта или подготовить его
  в интеграционной задаче. При упаковке новый TSS не создавался.
- Нет `Art/Preview/demo_world.jpg`, WAV-клипов и файлов шрифтов.
  Аудио-компонент без назначенных клипов молчит; фон демо не поставляется как текстура.
  Использовать ваши ресурсы. Шрифтовые назначения: Cinzel для латинских заголовков,
  Forum для кириллических, Manrope для основного UI; это рекомендации назначения.
- `StoneUIFxSurface.targetElement` по умолчанию ищет **name** `result-halo`, тогда как
  шаблоны задают его как **class**. При подключении эффекта нужно согласовать name/query;
  в этом архиве код и шаблоны оставлены без исправлений.
- 20 прэсетов в JSON не означают 20 полностью подключённых эффектов: runtime-аниматор
  обслуживает только реализованные tracks/call sites. Проверить reduced motion и pause.
- `Art/SourceOnly/` намеренно исключён installer из runtime-библиотеки: в архиве
  90 PNG, но список `library.art` после штатной сборки содержит **89** элементов.
  Декоративные исходные атласы не нужны как второй набор runtime-текстур.
- `wordmark_master` — исходный растровый фрагмент 386×87; `emblem_master` — 70×78.
  Высокого разрешения или нового написания в архиве нет. Большие шторки сохраняют
  пропорции; правила 9-slice и linear masks брать из manifest.
- Профиль далёкого окружения использует опорный радиус 36 м, слой 0 и рекомендуемый
  far clip 3000, не измеренные параметры актуальной сцены. Согласовать слой/culling,
  освещение, LOD, дальность и неподвижный мировой origin отдельно. Не включать в сетевую
  физику; генератор декоративного окружения не должен заменять существующее окружение.

## Происхождение переноса и контроль целостности

В текущем файловом окружении были доступны 31 файл предыдущей выдачи и отдельно
концептуальный постер. Они включены **побайтно без изменений**. Отдельно сохранились
5 из 90 PNG; оставшиеся 85 извлечены **без потерь** из уже существующих атласов
строго по `rect_top_left` исходного manifest. Новых изображений, масштабирования,
перерисовки или изменения альфы нет; все 90 PNG проверены на равенство RGBA-пикселей
с соответствующими прямоугольниками атласов. У восстановленных PNG не утверждается
тождественность историческим байтам PNG-компрессии — гарантируется равенство пикселей.

Отдельные UXML не сохранились как вложения. В архив экспортированы 16 **уже описанных**
шаблонов `S` из существующего `Tools/build_views.py` с его исходной XML-обёрткой.
Новая структура экранов не придумывалась; имена узлов и кнопок сверены с существующим
`screen_contract.json`. Исходные C#, шейдеры, Python, USS, config, manifest и атласы
не пересоздавались и не изменялись. Единственный новый авторский документ — этот handoff.

Проверки упаковки: SHA-256 исходных файлов до/после, 5 атласов, 90 PNG и размеры/пиксели,
16 корректно разбираемых XML и их контракты, JSON, ссылки USS на графику, CRC ZIP.
Это проверки переноса, **не** подтверждение готовности проекта к запуску в Unity.
