Host actor 2 consumes semantic held/pressed/released/pointer/scroll/camera frames through the existing EarthInputAdapter -> ActionRouter -> MagicInput pipeline. Existing quick-stone, grabs, continuous vector/gravity, wall/platform fit, wave, armor, surf, repair and return code therefore runs on the host. Held controls expire after traffic stops, and stale continuous samples coalesce without discarding press/release/scroll edges. Client damage, duel clocks/restart and cast gates stay disabled even if recovery re-enables a component.

Host publishes root/health/stun/recovery/score/timer and accepted hit facts. HitRegion occupies CombatState flags bits 24-31; clients never recalculate body region. Existing animation/HUD/field VFX getters read a separate accepted ability view, including held-body proxy, phase, charge, gravity/vector, armor and surf. The view does not write physics/control state. Full cosmetic bone synchronization is outside the approved requirement.

## World registry

Source roots contain Earth pools, arena structures, both boulders and dedicated armor/surf visuals. They must exclude planet chunks, actor/ragdoll colliders, camera/HUD and the replica root. All client world mutators, especially instanced pillar-wave rendering, belong in clientSuspendedMutators. Replica root has identity world transform. Generated proxies have no damage, fracture, mass or ownership solvers.

Run Elemental/Online/Bake Geometry Catalog Only after importing. It creates a deterministic GUID/local-file-ID catalogue of authored mesh/material/physics-material assets and dependency hashes without changing a scene. Runtime generated CPU-readable triangle meshes transfer positions, normals, tangents, UV/UV2, Color32 and material submeshes via compressed checked chunks. Known shader overrides preserve fracture mapping, armor palette and magic glow. Host node IDs begin at 1000 and last for that node lifetime; canonical actor IDs are 1/2. These visual/collision IDs are not the underlying EarthMatterRegistry IDs and are never used by a client to authorize a target. Semantic input is resolved against the host world.

Initial world data is reliable and paced, ends with node-count validation and ACK. Subsequent reliable create/change/despawn updates mirror the actual renderer/collider graph, including detached and repaired cells, while moving nodes get transient pose updates. Static nodes do not consume perpetual pose traffic. The client does not receive or simulate a second wall bond graph: exact visible/collision results come from the host graph. Limits: 4096 nodes, 4096 unique generated meshes, 8 MiB raw per mesh, 512 KiB/s geometry pacing and 128 changed node poses per 50 ms. Large fracture latency and CPU/GC costs still require profiling.

Terrain captures complete actual SdfEdit batches after state/halo version updates. The client applies the same sequence/kind/material/endpoints/radius and transactional mode, then validates every touched coordinate, version and content hash. A mismatch fails the connection. Fresh scene loading is required before another online session if terrain changed.

## Remaining integration and acceptance

The targeted Elemental/Online/Install EarthCoreSlice Online Only menu is prepared in Editor/OnlineArenaAuthoring.cs. Root executes installation and SDK compilation after importing. See INSTALLER.md. Required two-process evidence: create/join/cancel/disconnect, both-ready/geometry ACK barrier, actor-2 full toolkit, independent stunned/KO actor command rejection, client prediction, one accepted localized hit, wall/boulder destruction, terrain extraction/return hashes, and result/return-to-menu recovery. A room code or offline compiler pass is not gameplay acceptance.

Known presentational scope: no full cosmetic bone stream, no replication of arbitrary GPU-only VFX/indirect debris, no client-side mutation prediction, no host migration/resume/late join. Existing accepted state drives field/character presentation, but local cast preview responsiveness must be checked in the two-process run. Runtime meshes modified in place without changing bounds/vertex count require an explicit revision signal before supporting such a generator; current registry detects reference/bounds/count changes.
